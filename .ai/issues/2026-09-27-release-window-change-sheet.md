## Narrow ingress change, still needing an approved production responder

Use one owned, separately named file-provider YAML for an exact-host, non-redirecting 503 fence. It must have **four** target routers: HTTP and HTTPS for each of `allplan.net.tr` and `api.allplan.net.tr`, each at priority above the existing frontend's 9000 and the API's implicit priority. They all point to one pinned, non-customer-data maintenance responder on the existing shared application network. The responder returns HTTP 503 with `Retry-After`, no `Location`; health and image identity must be checked before admitting it into Traefik. Run it without application credentials, host ports, Docker socket or writable app mounts; use a read-only root, non-root user, dropped capabilities, no-new-privileges and bounded resources where its image supports them. Do not revive `allplan-maintenance-20260904`: it covers only the frontend host and historically redirects to the old site. Do not edit existing proxy files or restart the shared proxy as a shortcut.

Two isolated Traefik 3.6.7 rehearsals now support the **single-file, same-name** service-only → active → service-only method. The second rehearsal used four exact-host priority-10000 routers (HTTP and HTTPS for both target hosts), a synthetic locally trusted two-SAN certificate and a digest-pinned `node:22-alpine` Linux/amd64 responder (`node@sha256:0a7108bf6c7bf5de370ffb1a3ed6be93d405b43ff159f681a8d18c0e2bc2e402`).
